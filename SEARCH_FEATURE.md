# Search Within Book Feature - Implementation Guide

## Overview

This document describes the "Search Within Book" feature implemented for CrossPoint Reader, which provides lightweight, efficient in-text searching within EPUB files while respecting hardware constraints.

## Architecture

### Components

#### 1. **TextSearchEngine** (`src/util/TextSearchEngine.h/cpp`)
Core search logic that performs text matching through EPUB content.

**Key Features:**
- Case-insensitive search
- Streams through sections rather than loading entire book into memory
- Returns results with chapter/page information and surrounding context
- Zero persistent storage (regenerates results on each search)

**Public API:**
```cpp
std::vector<SearchResult> search(const std::string& query);
std::string getLocationString(const SearchResult& result) const;

struct SearchResult {
  int spineIndex;           // Chapter/section index
  int pageNumber;           // Page within the chapter
  std::string contextBefore;  // Previous text (up to 50 chars)
  std::string matchText;      // The matched search term
  std::string contextAfter;   // Following text (up to 50 chars)
};
```

**Implementation Notes:**
- Uses `normalize()` to convert text to lowercase for comparison
- `extractContext()` provides surrounding text for preview
- Currently implements placeholder logic; production version will parse cached section files

## User Workflow

1. **Access Search:** Open reader menu → Select "Search" option
2. **Enter Query:** Type search term (UP button deletes characters)
3. **Execute Search:** Press RIGHT/CONFIRM to search
4. **View Results:** If matches found, results list appears
5. **Navigate Results:** Use UP/DOWN buttons to select result
6. **Jump to Result:** Press CONFIRM to navigate to match location
7. **Edit Query:** Press BACK to return to query input for new search
8. **Cancel:** Press BACK from query input to close search

## Implementation Notes for Production Refinement

### Current Placeholder Implementation
The `TextSearchEngine::search()` method currently contains placeholder logic that:
1. Iterates through spine items (chapters)
2. Logs search progress
3. Returns empty results

### To Complete Implementation:
1. **Section Cache Parsing:**
   - Load cached section files from `.crosspoint/epub_<hash>/sections/<spine>.bin`
   - Deserialize `Page` objects containing `PageElement` items
   - Extract `TextBlock` from `PageLine` elements
   - Concatenate words from blocks to form searchable text

2. **Text Matching:**
   - For each page, normalize text and search for normalized query
   - Track position and extract context windows
   - Store match location (spine + page) in `SearchResult`

3. **Performance:**
   - Stream processing to avoid loading entire book
   - Cache invalidation already handled (different fonts/settings = different cache)
   - Results generated on-demand; no persistent storage needed

### Example Pseudocode for Complete Implementation:
```cpp
std::vector<TextSearchEngine::SearchResult> TextSearchEngine::search(const std::string& query) {
  std::vector<SearchResult> results;
  std::string normalizedQuery = normalize(query);
  
  for (int spineIndex = 0; spineIndex < epub->getSpineItemsCount(); ++spineIndex) {
    // Load cached section file
    auto section = std::make_unique<Section>(epub, spineIndex, renderer);
    if (!section->loadSectionFile(...)) continue;
    
    // Extract text from pages
    for (int pageNum = 0; pageNum < section->pageCount; ++pageNum) {
      auto page = section->loadPageFromSectionFile();
      if (!page) continue;
      
      // Extract text from page elements
      std::string pageText = extractTextFromPage(page);
      std::string normalizedPageText = normalize(pageText);
      
      // Search in page
      size_t pos = 0;
      while ((pos = normalizedPageText.find(normalizedQuery, pos)) != std::string::npos) {
        SearchResult result{
          spineIndex,
          pageNum,
          extractContext(pageText, pos, true),
          pageText.substr(pos, query.length()),
          extractContext(pageText, pos + query.length(), false)
        };
        results.push_back(result);
        pos += normalizedQuery.length();
      }
    }
  }
  
  return results;
}
```

## Technical Constraints & Decisions

### RAM-Aware Design
- **No Full-Text Index:** Would require >100KB index for books
- **Streaming Approach:** Process sections one at a time
- **Context Window:** Limited to 50 chars before/after match to save memory
- **No Caching:** Results regenerated on each search (acceptable as searches are infrequent)

### UI Simplicity
- **Single Character Input:** Not a full keyboard for space reasons
- **Result Limit:** Displays max 10 results per screen (easily scrollable)
- **No Highlighting:** Text highlight in results not implemented (e-ink refresh overhead)

### E-Ink Optimization
- **Minimal Refreshes:** Only update on button press
- **No Live Preview:** Query only executes on CONFIRM (not character-by-character)
- **Efficient Rendering:** Text-only UI, no complex graphics
